Ontology Identity Resolution — SPARQL query that powers every cross-system metric

PREFIX hosp: <http://hospitality.example.org/ontology#>
SELECT ?epos_id ?infor_code ?sap_cc ?sf_org ?site_name WHERE {
    ?site hosp:eposSiteId    ?epos_id    ;
          hosp:inforSiteCode ?infor_code ;
          hosp:sapCostCenter ?sap_cc     ;
          hosp:sfOrgUnitId   ?sf_org     ;
          hosp:siteName      ?site_name .
    FILTER(?epos_id = "SITE-LDN-01")
}
➜  epos_id="SITE-LDN-01"  ·  infor_code="GBR_SITE_0001"  ·  sap_cc="CC-GBR-001"  ·  sf_org="OU-GBR-001"  ·  site_name="London Canary Wharf"

Without this resolution, Infor WFM / SAP S/4HANA / SuccessFactors queries return 0 rows — their site_id formats don’t match EPOS. The ontology is the only key that connects all five systems. In production, AWS COA runs the equivalent query against its Virtual Knowledge Graph (Ontop) over Amazon Neptune.
